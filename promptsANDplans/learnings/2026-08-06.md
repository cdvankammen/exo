| L25 | **A machine-level environment problem can look exactly like a code/PR problem.** "Model failed on Linux but works on Macs" → we suspected layers, PRs, placement — it was the CUDA toolkit version. | Qwen3.5 failure investigation | Check GPU arch + CUDA toolchain version FIRST when a model fails on one backend only |
| L26 | **uv.lock can be out of sync with pyproject.toml** — torch declared for linux (`sys_platform == 'linux'`) but lock markers never resolve on linux with plain `--extra mlx` → torch silently absent → vision gracefully disabled. **FIXED by commit `f48bdf86`**: manually simplified the 3 torch/torchaudio/torchvision markers to `sys_platform == 'linux' and extra == 'mlx'` (the `extra != 'mlx-cpu'...` clauses from #2103's extra layout are mis-evaluated by uv 0.12.x). ⚠️ `uv lock` REGENERATION RE-BREAKS IT — re-apply the 3-line patch after any regen (verified twice). | `ModuleNotFoundError: No module named 'torch'` on Linux vision load | Check lock markers vs pyproject; fix = manual marker patch + `uv sync --extra mlx --dry-run` verification on the box |
| L27 | **One-sided RDMA edges cause JACCL segfaults.** Mac's info gatherer labels en2 as RDMA; Linux VM has no RDMA hardware but the edge was still created → `mx.distributed.init(backend="jaccl")` → signal 11 on the Mac runner. | 2-node Mac+Linux placement died with segfault | RDMA edges must require BOTH endpoints report RDMA; single-node placement avoids distributed init entirely |
